# 业务流程泳道图（可点可改）

单文件离线 HTML；以虚构采购申请为示例，包含申请人、审批人、系统三个泳道，六个节点与通过/驳回分支。适合产品经理做跨角色流程评审，逐步说明由谁处理、失败后从哪里恢复。

## 用处

流程设计页可点击节点、修改名称与说明、调整责任泳道；分支演示页可走通过或驳回补充重提；运行记录页查看本次演示产生的结果。它是业务评审原型，节点位置和流程拓扑在 DATA 中改，不是拖拽画布编辑器或真实审批系统。

| 页面 | 可直达状态 | 数量 |
|---|---|---|
| 流程设计 `design` | `normal` 正常/编辑、`empty` 空流程、`loading` 加载、`error` 加载失败 | 4 |
| 分支演示 `run` | `normal` 从头开始、`reject` 驳回补充、`done` 通过完成、`error` 执行失败 | 4 |
| 运行记录 `records` | `normal` 正常、`empty` 暂无记录、`loading` 加载、`error` 加载失败 | 4 |

共 **3 页 / 12 态**。逐步运行中的当前节点与校验提示属于交互结果，不另计面板状态。

## 用法

1. 解压 `ui-flow.zip`，双击 `index.html`，无需服务器。所有内容与脚本已内联，不请求外部资源。
2. 右下角「原型面板」切页和状态；按 H 隐藏；直达示例：`index.html#page=run&state=reject`。
3. 脚本顶部 `DATA` 管理标题、版本、责任泳道、节点、分支连线和运行记录。`nodes` 的 `id` 必须唯一，`edges` 引用有效节点；`x/y` 是画布坐标。调整位置时一并检查连线路径和标签是否重叠。
4. 在流程设计页点节点，填写名称、泳道和说明，点「保存节点」；名称和说明必填。切换节点或页面会放弃尚未保存的输入；先保存再切换。
5. 修改只保留在本次页面内存。点「导出 JSON」下载当前 DATA，需要持久保留时将 JSON 内容替换 HTML 中的 DATA 对象；没有自动导入功能。
6. 颜色、字体、间距、圆角等在 `:root`，画布尺寸在 `--flow-*`；较窄屏幕在图内横向滚动，节点表单移到图下。
7. 顶部「AI 提示词 · 一键复制」可打开三条提示词，业务变量可点击就地填写。

## 交互说明

| 元素 | 交互 | 反馈 |
|---|---|---|
| 导航 / 原型面板 | 切换页面、状态 | 同步页面内容和地址片段 |
| 泳道节点 | 点击或 Tab + Enter | 选中框高亮，右侧显示该节点详情 |
| 节点表单 | 修改并保存 | 必填校验；保存后名称、说明、责任泳道与连线同步更新 |
| 节点类型 | 查看实线/虚线/圆角边框 | 区分任务、判断和开始/结束节点 |
| 连线标签 | 查看箭头与标签 | 分别表示提交、校验、通过、驳回、重提和完成 |
| 执行下一步 | 逐步点击 | 当前节点高亮，已执行节点使用成功边框，轨迹追加一条 |
| 审批通过 | 点击通过 | 生成采购单 → 通知申请人；完成后新增一条示例运行记录 |
| 审批驳回 | 填写原因后点击 | 原因不能为空；回到补充节点，重提后再次审批 |
| 执行失败 | 点击重试 | 显示加载，随后从生成采购单继续，不重走审批 |
| 重置演示 | 点击 | 从第一个节点重新开始，已有完成记录保留 |
| 运行记录 | 点击查看详情 | 弹窗显示编号、结果、名称、处理人与时间；Esc 或取消关闭 |
| 空流程 | 使用示例流程 | 返回六节点示例设计 |
| 空运行记录 | 开始演示 | 打开从头演示 |
| 导出 JSON | 点击 | 下载本次修改后的 DATA，文件名明确标为示例 |
| AI 提示词变量 | 点击填写、复制 | 复制结果自动替换变量 |

直接选择面板「通过完成」只预览完成态，不产生新记录；逐步执行到终点才产生记录。运行轨迹属于本轮演示，切换面板状态会重置。

## AI 提示词

下面内容与页面面板一致；带 `{{变量}}` 的部分可在面板就地填写。

### 1. 从零生成这个原型

请用单文件 HTML 制作业务流程泳道图，双击离线可开。包含申请人、审批人、系统三个泳道，开始/结束、任务、判断节点和有方向及分支标签的连线。点击节点查看说明并编辑名称、责任泳道和描述，保存后同步到图中。包含流程设计、逐步分支演示、运行记录三个页面，可演示通过、驳回补充重提、系统失败重试；各页补正常/空/加载/出错，原型面板可切。业务数据集中 DATA，样式集中 CSS 变量，内联 SVG 图标，全部示例数据标示例。附交互说明表和三条可复制 AI 提示词，支持变量就地填写。

### 2. 改成我的业务

请把附件泳道图改成{{业务名称}}。角色泳道是{{角色列表}}，节点与说明是{{节点列表}}，分支规则是{{通过条件与驳回条件}}，结束时产物是{{业务产物}}。更新 DATA、图上连线、节点详情、分支演示和运行记录，使责任人与路径一致。保留正常/空/加载/出错和返回路径、CSS 变量、离线能力、原型面板与提示词面板。所有数据用虚构示例，交付完整 HTML 和更新的交互说明表。

### 3. 加页面或状态

请在附件原型中增加{{新增页面或状态}}，触发条件为{{触发条件}}，由{{负责角色}}处理，处理后的去向为{{后续节点}}。同步新增泳道节点、判断连线、步骤演示、运行记录与原型面板入口，覆盖取消、失败和重试，不产生重复记录。沿用现有 CSS 变量、DATA、单文件离线结构，交付完整 HTML 与新增交互说明。
