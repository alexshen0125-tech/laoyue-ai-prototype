# Webhook 与集成配置

中文离线单文件，打开 index.html；顶部下载同名zip。保留主题、目录搜索、静态HTML与提示词复制。

## 事件主题与载荷
在主题目录中选择一种业务事件，预览投递契约后启用本地订阅。
什么时候用：集成方确认自己消费的业务变化类型。
什么时候别用：订阅配置页不能代替下游履约事务。
交互规则：只接受HTTPS地址；启用显示所选主题JSON；暂停后保留目标地址。
状态：订阅契约草稿 / 目标地址不安全 / 主题订阅已启用 / 订阅投递已暂停

## 按响应码退避
临时错误进入指数退避，永久请求错误直接停止并给出载荷修正建议。
什么时候用：服务短暂不可用且事件消费具备幂等性。
什么时候别用：400参数错误不应靠增加次数解决。
交互规则：重试0至8次；429和503可重试；400不重试；延迟为2的尝试次数次方秒。
状态：响应回执待分类 / 永久错误不重试 / 退避计划就绪 / 次数耗尽入死信

## 时间戳与重复请求检查
把签名校验之前的时效门槛和事件编号去重单独展示。
什么时候用：排查时钟偏移或重复回调被拒绝。
什么时候别用：离线页面不计算密钥签名或证明请求身份。
交互规则：时窗30至600秒；偏差取绝对值；evt_7900已消费；本页不执行HMAC。
状态：验签前置参数 / 请求超出时窗 / 重复事件已拒绝 / 时效检查放行

## 死信重放与幂等
保留失败原因和原事件ID，修复目标后仅对未消费事件建立重放批次。
什么时候用：下游修复完成后追回失败通知。
什么时候别用：不要为已经消费的事件创建新业务单据。
交互规则：健康检查通过才可重放；批次含两条失败事件；重放后按钮锁定。
状态：死信等待修复 / 目标仍不健康 / 可重放两条事件 / 重放批次已登记

## 请求超时与回执
将下游耗时与连接超时分开，超时后的投递结果标为未知。
什么时候用：评估慢接口是否应异步接收事件。
什么时候别用：超时不能直接判定下游业务未执行。
交互规则：耗时固定12秒；超时1至30秒；超时后先查幂等回执再结束追踪。
状态：投递时限设置 / 超时结果未知 / 回执确认已消费 / 在时限内收到200
