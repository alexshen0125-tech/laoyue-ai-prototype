# 需求反馈与投票

免费下载 · 双击就能打开 · 复制提示词直接给 AI 用。

将问题描述、投票合并、路线图与交付回访组织成公开反馈入口。

打开 index.html 离线使用，数据为虚构，操作仅在本页有效。

## 反馈需求提报
记录用户场景、受影响角色与预期变化。
适用：用户希望团队理解真正的问题。
不适用：紧急故障应走客服或故障通道。
规则：标题至少六字，场景至少十二字。
状态：需求场景待写、反馈描述不足、需求材料可交、产品反馈已记

## 候选需求投票
五个需求各自展示支持票数与当前参与状态。
适用：团队了解用户对改进点的偏好。
不适用：票数不能单独决定开发优先级。
规则：每个需求最多一票；可撤回自己的支持。
状态：候选需求待看、当前支持撤回、支持需求可选、用户投票已记

## 重复需求合并
对比两条导出需求的目标和边界后合并。
适用：运营整理措辞不同的同类诉求。
不适用：不同权限场景不能只因标题相似合并。
规则：须确认业务范围一致；原反馈保留跳转关系。
状态：疑似重复待比、合并范围未核、重复反馈可并、需求关联已并

## 产品路线图订阅
按调研、计划和交付分栏展示五个需求。
适用：用户查看关注改进的进展。
不适用：计划月份不构成交付承诺。
规则：可订阅或取消需求进展；本地操作不发送消息。
状态：需求路线待看、路线订阅取消、需求进展可订、路线关注已记

## 交付效果回访
展示已交付改进与满意度并收集使用反馈。
适用：产品经理验证问题是否解决。
不适用：满意度分数不等于业务收益。
规则：评分1至5，使用反馈至少十字。
状态：交付回访待填、回访内容不足、改进效果可交、用户回访已记
