# 版本发布与公告

打开 index.html 即可离线使用，支持深浅主题、做法搜索、状态快照、提示词复制、HTML复制与模块ZIP下载。

## 变更条目编排

将技术提交转换成用户能理解的变化，并区分新增、优化与修复。

什么时候用：产品准备面向客户发布版本更新说明。

什么时候别用：内部密钥和未公开漏洞细节不得出现在公告条目中。

状态：版本说明草稿 / 条目缺少影响描述 / 变更条目已收录 / 说明待法务复核

操作：收录版本条目。变化描述至少12字，按新增、优化或修复追加到2.18.0草稿。

## 受众与渠道预览

按客户角色选择发布渠道，用一段真实公告预览核对信息层次。

什么时候用：同一版本需要向管理员和门店员工传递不同提示。

什么时候别用：紧急中断通知不应仅靠低触达的帮助中心文章。

状态：公告受众待选 / 渠道触达不足 / 渠道预览已生成 / 受众名单为空

操作：生成渠道预览。停机公告不能仅发帮助中心，预览明确角色人数和主动触达渠道。

## 发布窗口与冲突

避开业务结算与仓库波次，发布时间必须同时考虑维护和使用时区。

什么时候用：上线涉及短暂停机，需要确定客户可接受的窗口。

什么时候别用：无需停机的文案调整不必套用完整维护流程。

状态：上线窗口待排 / 窗口不符合约束 / 维护窗口已登记 / 发布日已过去

操作：登记维护窗口。上线日须晚于演示基准日，小时限定02至03点的低峰窗口。

## 发布门禁核验

上线之前逐项检查备份、回滚和客户告知，缺一项就保留发布门禁。

什么时候用：值班发布负责人需要确认上线准备完成。

什么时候别用：勾选记录不能代替真实监控或备份可恢复验证。

状态：发布门禁未放行 / 发布证据未齐 / 发布已获本地放行 / 灰度指标异常

操作：核验发布门禁。五项证据均确认才记为本地放行，此页面不执行部署。

## 公告更正与撤回

已发布公告保留原文和更正原因，避免静默改动客户曾经看到的承诺。

什么时候用：上线后发现公告时间或影响范围写错，需要显式更正。

什么时候别用：不得用撤回公告掩盖已经发生的线上事故。

状态：公告已发布 / 更正理由不足 / 更正记录已追加 / 公告已撤回

操作：追加公告更正。未发布的2.18.0应直接改草稿；历史公告更正至少12字且保留原文。
