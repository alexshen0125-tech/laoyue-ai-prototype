# 退款与退货处理

中文离线单文件。打开 index.html；顶部可下载本模块 zip。

## 部分退款核算
订单实付、历史已退与本次退款并列展示，先计算剩余额度。
什么时候用：部分商品缺货或服务补偿需要退回部分实付款。
什么时候别用：线下现金补偿不能伪装成原路退款。
状态：退款金额草稿 / 超过剩余可退 / 金额已核对 / 退款申请已建立
交互：实付680元、已退80元，最多再退600元；精确到分且必须大于0。

## 退货入库验收
将顾客申请数量与仓库实收、破损情况对照，质量不符时保留异常照片说明。
什么时候用：退款需要等待实物回仓并确认数量。
什么时候别用：仅退款无需退货时不应强迫创建入库验收。
状态：等待回仓 / 实收数量不符 / 货损待复核 / 验收通过可退款
交互：申请退2件，实收不得超申请；少件和破损进入人工复核，不直接放款。

## 原支付渠道分配
混合支付订单分别计算现金渠道、余额和优惠券的处理方式。
什么时候用：退款涉及多种付款工具，需要解释到账差异。
什么时候别用：优惠券面额不能当作现金重复退还。
状态：混合支付明细 / 原渠道待处理 / 现金到账延迟 / 全部渠道完成
交互：订单现金支付480元、余额200元、券50元；实付退款680元分原渠道退。

## 退款审核与驳回
审核人对申请理由与凭证做判断，驳回必须留下客户可理解的原因。
什么时候用：超出自动退款范围的售后申请需要人工决策。
什么时候别用：审核不能修改客户已支付的真实订单金额。
状态：退款待审批 / 驳回说明缺失 / 申请已驳回 / 审批已通过
交互：退款理由至少6字；驳回需具体说明；提交后同一审核单不重复处理。

## 未知结果与安全重试
支付渠道超时先查原退款单状态，不能立即重复创建退款请求。
什么时候用：渠道返回超时或处理中，结果尚不明确。
什么时候别用：已到账的退款不应再次触发退款执行。
状态：退款结果未知 / 渠道仍处理中 / 渠道确认失败 / 原单重试成功 / 查询确认已到账
交互：固定退款单RF-261184；先查再重试；查到成功不再执行，失败重试沿用原单号。
