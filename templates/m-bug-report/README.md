# 缺陷提报与复现

打开 index.html 即可离线使用，支持深浅主题、做法搜索、状态快照、提示词复制、HTML复制与模块ZIP下载。

## 结构化复现步骤

把操作、预期和实际结果分开记录，减少工程师来回追问。

什么时候用：测试发现稳定重现的问题，需要提交给开发定位。

什么时候别用：尚未确认需求的行为差异应先做产品澄清。

状态：缺陷记录草稿 / 复现证据不足 / 缺陷已提报 / 重复缺陷待合并

操作：提报复现记录。标题至少8字，实际结果至少10字，五步操作随缺陷一起保留。

## 环境矩阵比对

按系统与浏览器分列复现概率，避免把单端问题误判成全站故障。

什么时候用：同一缺陷在不同客户端表现不一致。

什么时候别用：矩阵中的演示结果不能替代真实设备测试。

状态：环境待比对 / 构建号不完整 / 环境结论已标注 / 版本信息缺失

操作：标注影响环境。构建号须采用六位日期加序号格式，环境结论保留各端命中次数。

## 证据脱敏预览

提交前扫描日志里的手机号和令牌，把敏感字段替换成可分享标记。

什么时候用：定位接口异常需要附带最小必要日志。

什么时候别用：自动替换无法识别所有秘密，仍要人工审阅。

状态：日志待脱敏 / 日志文本为空 / 脱敏副本已生成 / 附件类型不支持

操作：生成脱敏副本。输入非空日志后遮盖手机号和token，原文保留但不自动分享。

## 影响分级与指派

结合影响范围与绕行方案评估优先级，故障级别不由标题情绪决定。

什么时候用：值班人员需要将缺陷分配到合适的处理队列。

什么时候别用：安全漏洞请走专用安全通报，不公开附上利用细节。

状态：缺陷待分级 / 严重级别冲突 / 责任组已指派 / 处理人排班空缺

操作：确认分级与指派。本案有绕行方案，拒绝标记P0，其他等级可进入所选责任组。

## 修复回归与重开

逐条核对修复后的关键场景，任一失败都阻止缺陷关闭。

什么时候用：开发提交修复后，测试需要留下回归结论。

什么时候别用：只验证开发截图不能视为回归通过。

状态：修复包待回归 / 回归覆盖不完整 / 缺陷已关闭 / 缺陷已重开

操作：提交回归结论。五项回归必须全部勾选；缺项时缺陷继续开放。
