# 会议预约与纪要

离线单文件原型，双击 index.html 打开。顶部提供同名zip免费下载。外壳直接采用 m-contract 的 _kit 标准。

## 会议室冲突预约
将已有占用时段与新预约直接对照，禁止覆盖冲突。
什么时候用：跨团队会议需要固定会议室。
什么时候别用：临时语音讨论不必占用线下空间。
状态：预约时段待选 / 会议室时段冲突 / 资源时段可预订 / 会议室已锁定
交互规则：11月12日10至11点占用；按整点预约1小时。

## 议题与时间盒
为五项议题分配讨论时间，超时先调整再定稿。
什么时候用：评审会前需要控制讨论范围。
什么时候别用：发散工作坊无需强行按此60分钟模板。
状态：议题时间待分配 / 议程超出会议时长 / 时间盒已平衡 / 会议议程已定稿
交互规则：总时长为固定45分钟加决策时长，不得超过60。

## 参会回应与法定人数
把关键决策人回应与普通参会人数分别展示。
什么时候用：方案评审必须有产品负责人参加。
什么时候别用：开放分享会不适用关键决策人门槛。
状态：关键参会人待回应 / 决策人无法出席 / 参会条件已具备 / 会议签到已登记
交互规则：产品负责人拒绝时禁止开始决策；待回应需催办。

## 纪要结论与确认
将讨论记录浓缩为可确认的决策，不把建议误作已通过事项。
什么时候用：会后需要让负责人核对最终结论。
什么时候别用：逐字稿不应直接替代决策确认。
状态：纪要结论草拟 / 决策描述过短 / 纪要退回修订 / 会议结论已确认
交互规则：结论至少12字；退回后仍保留原始记录。

## 行动项责任追踪
为会议决定绑定负责人和截止日期，完成时留下交付证据。
什么时候用：讨论结束后需要跟进具体交付。
什么时候别用：纯通知会议可无需创建行动跟踪。
状态：行动项待分派 / 行动责任人缺失 / 任务已分派 / 行动交付已验收
交互规则：责任人不能为空；完成证据至少8字。

### 跟进行动责任
围绕{{评审}}建立行动项清单，逐项明确责任人、截止日和交付证据，验收后保留结果。
