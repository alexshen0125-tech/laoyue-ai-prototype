# 企业开通引导

离线单文件原型，双击 index.html 打开。顶部提供同名zip免费下载。外壳直接采用 m-contract 的 _kit 标准。

## 企业主体与工作区
用企业名称与域名建立独立工作区，避免重名开通。
什么时候用：企业第一次接入协作产品。
什么时候别用：已有租户应走加入团队而非重新开通。
状态：企业资料待填 / 工作区域名已占用 / 工作区名称可用 / 企业工作区已建立
交互规则：域名前缀为3至20位小写字母数字或横线；qinghe已占用。

## 管理员邀请与席位
明确每位受邀者的职责，超出席位额度前先减少邀请。
什么时候用：开通时组建企业管理员和试点小组。
什么时候别用：外部合作方不能默认获得管理员角色。
状态：团队成员待邀请 / 邀请邮箱或席位受限 / 试点邀请可创建 / 入驻邀请已登记
交互规则：已有4席；总额度5席；新增邮箱不得重复且格式有效。

## 部门映射与数据试导
导入前预览组织层级，无法映射的部门不落入默认组。
什么时候用：企业已有HR花名册需要快速建立团队。
什么时候别用：只有几名员工时可直接手动添加。
状态：组织映射待补 / 存在未映射部门 / 五条数据可试导 / 试点成员已导入
交互规则：华东门店必须绑定一个目标部门；通过后模拟导入5条。

## 安全基线与管理员权限
开通前要求管理员启用二次验证并限制外部访问。
什么时候用：企业需要在员工加入前确定基础安全策略。
什么时候别用：演示勾选不会实际改变身份服务设置。
状态：安全基线待设置 / 管理员未启用验证 / 外部共享需收紧 / 企业安全基线已确认
交互规则：二次验证必须启用；外部共享必须关闭才能继续。

## 开通检查与试点交接
把各阶段验收清单汇总到上线门槛，交接后进入试点运营。
什么时候用：配置完成后由管理员确认第一批使用范围。
什么时候别用：完成开通不代表后续数据治理工作结束。
状态：上线清单待确认 / 仍有开通项未验收 / 试点开通条件齐备 / 企业试点已交接
交互规则：必须确认全部5项；未完成时显示缺项数量。

## AI 提示词

### 设计企业入驻
为{{企业}}设计企业名称与工作区域名核对，区分新建租户和加入既有团队，域名冲突时引导联系管理员。

### 安排团队试点
按{{团队规模}}设置席位数和邀请邮箱核对，配合部门映射预览五条人员记录，未映射项阻断试导。

### 设置开通门槛
为{{企业名称}}建立二次验证、外部共享和交接清单，逐项完成后进入试点并展示支持联系人。
